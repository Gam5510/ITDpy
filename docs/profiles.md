# ITDpy

## Профили (мульти-аккаунт)

`ITDClient` умеет сохранять данные сессии (`refresh_token`, `access_token`,
время истечения access_token) на диск в виде именованного "профиля" и
переиспользовать их при следующем запуске — без повторной передачи
`refresh_token` или email/password.

Файл профилей по умолчанию: `~/.itdpy/profiles.json`
(на Windows — `%USERPROFILE%\.itdpy\profiles.json`), путь можно переопределить
через `profiles_path=`.

----------

## Как это работает

- `access_token` живёт около 15 минут, `refresh_token` — несколько дней.
  По умолчанию клиент обновляет `access_token` сам, каждые 13–14 минут
  (`auto_refresh_interval=(13*60, 14*60)`, интервал случайный в этом
  диапазоне), а также по 401. При каждом обновлении SDK декодирует время
  истечения из самого JWT (поле `exp`) и сохраняет его вместе с токенами
  в профиль.
- При повторном запуске с `profile=` сохранённый в файле `refresh_token`
  **всегда** используется вместо переданного в конструктор аргумента —
  это исключает ситуацию, когда в коде остаётся зашитый старый/отозванный
  токен, а актуальный (после ротации) лежит только в файле профиля.
- Если при создании клиента передан `profile=` и в файле профилей уже есть
  запись с ещё не истёкшим `access_token` — SDK возьмёт сохранённый
  `refresh_token` из файла и `refresh_token`/`email`/`password` в
  конструкторе передавать не обязательно.
- Если профиля с таким именем ещё нет — он будет создан автоматически
  сразу после первой успешной аутентификации.
- При ротации `refresh_token` (это происходит на каждом обновлении сессии)
  новое значение тоже сразу пишется в профиль — как обычным
  `_capture_rotated_refresh_token`, так и колбэком `on_refresh_token_update`,
  если он задан.

----------

## Пример использования

```python
from itdpy import ITDClient

# Первый запуск — токен ещё не сохранён
client = ITDClient(
    refresh_token="YOUR_REFRESH_TOKEN",
    profile="main",
)
print("access_token истекает:", client.access_expires_at)
client.close()
```

```python
# Повторный запуск (следующий старт приложения) — токен не нужен,
# SDK возьмёт его из ~/.itdpy/profiles.json, если он ещё не истёк
client = ITDClient(profile="main")
print(client.refresh_token)
client.close()
```

### Параметры конструктора, относящиеся к профилям

- `profile` — имя профиля (алиас аккаунта). Если не передан — поведение
  как раньше, ничего не сохраняется на диск.
- `profiles_path` — путь к JSON-файлу профилей (по умолчанию
  `~/.itdpy/profiles.json`).
